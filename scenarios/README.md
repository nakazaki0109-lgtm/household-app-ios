# シナリオ（mobile-mcp による動作確認）

機能ごとに1ファイルの手順書。Claude が mobile-mcp（`.mcp.json` で設定済み）でシミュレータを操作して実行し、期待結果ごとに合否を報告する。
`README.md` 以外の `*.md` がシナリオ。無人の自動テストではなく、Claude が画面を見て判定する確認手順として使う。

## 書き方

```markdown
# 機能名

前提: 空の初期状態        ← 「サンプルデータあり」か「空の初期状態」。必須

## 手順

1. 月別集計タブで `summary.addTransactionButton` をタップする
   - 期待: 「収支登録」画面が開く
```

- 操作対象は、`HouseholdApp/Views/AccessibilityID.swift` の識別子をバッククォートで書く。タブバーのボタンだけは識別子が付けられないので、ラベル（月別集計・収支一覧・予算設定）で書く
- 期待結果は「期待:」の行に1つずつ、画面で確かめられる形で書く。金額など日付以外の値は具体的に書き、日付は「当月」「今日」のように実行日に依存しない書き方にする
- 前提はシナリオごとに1つ。データ違いの確認は別ファイルに分ける
- 新しい機能を作ったら、その機能のシナリオを1ファイル追加する。画面を変えたら、影響するシナリオも直す（Claude が自動では書き換えないので、ユーザーの了承を得て直す）

## 実行のしかた

1. シナリオごとに、前提の状態でアプリを起動する。UDID と結果の保存先が表示される

   ```bash
   python3 -m scripts.scenario launch scenarios/<シナリオ>.md
   ```

   - 空の初期状態: アプリを入れ直して起動する（取引0件、既定の6カテゴリだけ）
   - サンプルデータあり: `-ScreenshotSampleData` 付きで起動する（スクリーンショット撮影と同じデータ）
   - 起動の前に、シミュレータ（iPhone 16）の起動・アプリのビルド・mobile-mcp のエージェントの導入まで行う。ビルドを飛ばすときは `--no-build`

2. 表示された UDID を `device` に指定して mobile-mcp を操作する。画面の確認は `mobile_list_elements_on_screen`（識別子は `id=` に出る）で行う。アプリの起動・終了に mobile-mcp の起動ツールは使わない（起動引数を渡せないため）
3. 手順を上から実行し、「期待:」ごとに合格・不合格を判定する
4. 結果を、保存先（`build/scenario-results/<シナリオ名>/`）の `result.md` に書く。`build/` は Git 管理外

## 失敗したとき

期待と画面が食い違ったら、その場で止める。

- `mobile_save_screenshot` で保存先に `failure.png` を保存する
- 次を報告する: 失敗した手順の番号、期待、実際の画面との違い、スクリーンショットのパス
- 以降の手順は実行しない。アプリのコードもシナリオも書き換えない。直すかどうかはユーザーが決める
- 複数のシナリオを続けて実行しているときは、失敗したシナリオだけ止めて次のシナリオへ進み、最後にシナリオごとの合否の一覧を報告する

## mobile-mcp を使うときの注意

- ボタンは識別子が同じ `Other` と `Button` の2要素で出ることがある。タップするのは `Button`
- 数字キーパッドは閉じるボタンが無く、開いている間はタブバーや画面下の入力欄が隠れる。画面の下半分にある入力欄（収支登録のメモ）は、金額より先に入力する
- 入力欄に文字を入れる前に、必ず欄をタップしてフォーカスを移す。`mobile_type_keys` は、フォーカスのある欄に入力する
- 要素の `ref`（`@e12` など）は一覧を取り直すたびに変わる。タップの直前に一覧を取得する
