# サブエージェント設計をスキルの中に閉じ込める

## 原則

スキルの中からサブエージェント（Agent/Taskツールで呼び出す別のエージェント）を使うなら、**そのサブエージェントの設計をスキル自身のディレクトリに閉じ込める**。

やってはいけないのは、SKILL.md の本文の中に「こういう指示のサブエージェントを飛ばす」という説明を長々と埋め込むこと。理由は2つ:

1. **本文が膨れる**: サブエージェントへの指示は、そのサブエージェントを実際に呼ぶときにしか要らない情報。SKILL.md 本文（発火するたびに読み込まれる層）に置くと、呼ばない場合でもコンテキストを圧迫する。progressive disclosure の考え方に反する。
2. **契約が曖昧になる**: 地の文に混ぜて書くと、「サブエージェントへの入力」「サブエージェントが返すべき出力」「やってはいけないこと」の境界があいまいになり、オーケストレーション側（親スキル）とサブエージェント側の役割が混線する。

## やり方

サブエージェントへの指示は `agents/<役割>.md` に切り出し、SKILL.md からは「いつ・何のためにこのファイルを読んでサブエージェントを飛ばすか」だけを書く。

```
skill-name/
└── agents/
    ├── grader.md        # 例: 出力を採点するサブエージェント
    └── analyzer.md       # 例: 結果の傾向を分析するサブエージェント
```

SKILL.md 側の書き方の例:

```markdown
## 採点する

`agents/grader.md` を読み、その指示に沿ってサブエージェントを1件ずつ起動する。
```

## `agents/*.md` に書くべきこと

各ファイルは、そのサブエージェント自身に向けた指示として書く（親スキルの視点ではなく、サブエージェントの視点で）。最低限、次の4つを含める。

- **役割**: このサブエージェントは何のために存在するか
- **入力**: 呼び出し元（親スキル）が渡してくるものは何か（パス、パラメータ、文脈）
- **出力**: 何を、どこに、どの形式で返すべきか。親スキル側がそのまま消費できる形を明記する
- **制約**: やってはいけないこと。特に「ユーザーに質問しない」「呼び出し元の意図を勝手に推測しない」など、サブエージェントには効かない前提（ユーザーとの対話ができない、会話の文脈を引き継いでいない）を明示する

## いつサブエージェントを使うか

- **並列化できる独立した作業**: 複数件を同時に調べる/生成する/採点するなど、互いに依存しない繰り返し作業
- **メインの文脈を汚さない探索**: 大量のログやコードを読む必要があるが、その過程自体は後段に不要な場合
- **独立した視点が要る判定**: バイアスのかからない比較・採点・レビューをさせたい場合(例: A/Bのブラインド比較)

逆に、単純な逐次ステップは親スキルがそのまま実行すればよい。「サブエージェントを使うこと」自体を目的化しない。
