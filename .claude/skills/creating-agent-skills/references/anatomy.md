# スキルの解剖図

## ディレクトリ構成

```
skill-name/
├── SKILL.md          必須。frontmatter (name, description) + 本文
├── references/        詳細情報。必要な時だけ読み込む
├── scripts/            決まった処理を任せるコード。単体テスト付き
│   └── tests/
└── agents/             サブエージェントに渡す指示（このスキルが使う場合のみ）
```

`SKILL.md` だけが必須で、残りは「そのスキルに実際に必要なものだけ」を足す。すべてのスキルに `references/` `scripts/` `agents/` を機械的に用意する必要はない。

## 3段階のロード（progressive disclosure）

1. **メタデータ**（`name` + `description`）: 常にモデルのコンテキストに載っている。トリガー判定はここだけで行われる。
2. **SKILL.md 本文**: スキルが発火したときにコンテキストへ読み込まれる。目安は500行以内。
3. **同梱リソース**（`references/` `scripts/` `agents/`）: 必要になったときだけ読み込む/実行する。ここは実質無制限。

この3段階を意識すると「何を SKILL.md に書き、何を切り出すか」が決めやすくなる。頻繁に参照するが短いものは本文に、量が多い・特定の分岐でしか要らないものは `references/` に、という基準で分ける。

## SKILL.md が肥大化してきたら

- 500行に近づいてきたら、まず「常に必要な部分」と「特定条件でしか要らない部分」を仕分ける
- 後者を `references/*.md` に切り出し、SKILL.md 側には「いつこのファイルを読むべきか」を一文で明記したポインタだけを残す
- 複数のドメイン/バリエーションを扱うスキルは、共通のワークフローを SKILL.md に残し、ドメインごとの詳細を `references/<domain>.md` に分ける

```
cloud-deploy/
├── SKILL.md            共通のワークフロー + どのファイルを読むかの分岐
└── references/
    ├── aws.md
    ├── gcp.md
    └── azure.md
```

- 300行を超える参照ファイルには目次を付ける

## Principle of Lack of Surprise

スキルの中身は、説明された意図から利用者が驚かないものであること。マルウェアや攻撃コード、不正アクセス・データ持ち出しを助けるような内容を含めない。
