# プロンプト文書の棚卸し

会社の規程が変わったときに社内の手順書を全部読み直して付箋を貼る係。**付箋を貼るところまでが仕事で、貼り替えるかどうかはユーザーが決める。**

## 絶対に守ること

**監査中は対象ファイルを編集しない。** 指摘と変更前後のdiffを提示する。ユーザーが修正を依頼したら、その範囲を反映する。個別の承認はその項目に、まとめて修正する依頼は対象の全項目に適用し、既に得た承認を聞き直さない。承認範囲外の提案は反映しない。

## 全体の流れ

1. 対象範囲を決める
2. 最新のプロンプト設計ガイドを取得する(`references/live-sources.md`)
3. 対象文書ごとに監査する(`references/timeless-checklist.md` + 取得したライブの内容)
4. 差分として提示し、承認された分だけ反映する

## 1. 対象範囲を決める

ユーザーが対象ファイルを指定していればそれに従う。指定がなければ、決まった探索処理はスクリプトに任せる:

```bash
python .claude/skills/auditing-prompt-docs/scripts/find_prompt_docs.py <リポジトリのルート>
```

`SKILL.md` / `CLAUDE.md` / `AGENTS.md` を再帰的に見つけて一覧を返す(`node_modules` `Pods` `DerivedData` などは自動で除外される)。ユーザー個人の `~/.claude` 配下のスキルやCLAUDE.mdも対象にしたいかは、必要そうなら確認する。

## 2. 最新のプロンプト設計ガイドを取得する

`references/live-sources.md` を読み、その手順どおりにWebFetchでAnthropic公式ガイドを取得する。**このスキルにローカルで同梱されているチェックリストは簡易版であり、正典ではない。** モデル固有の違いは毎回取得し直す。取得できない環境では、その旨を最終報告の冒頭に明記した上でローカルのチェックリストのみで進める。

## 3. 対象文書ごとに監査する

`references/timeless-checklist.md` の観点と、手順2で取得したモデル固有の最新差分の両方を使って各文書を確認する。

対象が複数件ある場合は、`agents/auditor.md` を読み、文書1件につき1つのサブエージェントを並列で起動して監査させる。独立した読み込み・判定作業であり、他の文書の結果を待つ必要がないため並列化に向く。サブエージェントには次を渡す:

- 対象ファイルの絶対パスと全文
- `references/timeless-checklist.md` の内容
- 手順2で取得した、今回のセッションを動かしているモデル向けの最新の差分

サブエージェントはファイルを書き換えず、指摘と修正案のテキストだけを返す(`agents/auditor.md` 参照)。対象が1件だけなら、サブエージェントを起動せずその場で監査してよい。

## 4. 差分として提示し、承認された分だけ反映する

サブエージェント(または自分)が出した修正案を一時ファイルに書き出し、次で現状とのunified diffを作る:

```bash
python .claude/skills/auditing-prompt-docs/scripts/render_diff.py <対象ファイル> <提案を書いた一時ファイル>
```

ファイルごとに、チェックリストの観点別の指摘とこのdiffをユーザーに提示する。ユーザーが個別に、あるいはまとめて承認した変更だけをEditツールで反映する。承認がない指摘は提案のまま残し、ファイルには触れない。

## いつ回すか(ユーザー側の目安)

- 新しいモデルがリリースされた時(メジャー・マイナー問わず)
- スキルや `CLAUDE.md` を調整した後、大きくなってきたと感じた時
- しばらく手入れしていないと感じた時
- 期待通りに動かなかった時、原因を掘り下げる前にまず一通り回してみる、という使い方もある(このスキル自身が万能の原因究明ではないことは伝えておく)
- 決め打ちにしたいなら、週1回程度の頻度でも十分

## 参照ファイル

- `references/live-sources.md` — 毎回取得し直すAnthropic公式ガイドのURLと読み方
- `references/timeless-checklist.md` — バージョンが変わっても大きくは崩れない簡易チェックリスト(ライブの内容と食い違ったらライブを優先)
- `agents/auditor.md` — 文書監査サブエージェントへの指示(役割・入力・出力・制約)
